# ADR-013：检索迁移影子评测偏差

- 状态：Proposed / Pending Architecture Owner Approval
- 日期：2026-07-26
- 修改基线：技术设计 v1.0 Phase 5、Phase 6

## 背景

旧检索路径已从生产代码删除，新检索路径已经是唯一在线实现。仓库没有保存能够证明
Phase 5 曾按“新旧链并行、仅旧链回答”运行的逐请求 Trace；当前
`baseline_ranked_chunks` 是新链内部 RRF 候选，不是旧链输出。事后恢复旧在线链只为补
迁移证据，会重新引入已经删除的 JSON 索引、关键词计数和完整 Markdown 路由，并扩大
生产回滚面。

## 决策

不重新引入旧生产链，也不把新链内部 fused/reranked 对比描述成 old/new shadow。
Phase 5 改为对同一份脱敏 Golden Dataset 运行隔离回放：

1. 保留旧链已有基线作为历史参考，不作为发布 Gate；
2. 新链必须走真实 PostgreSQL FTS、pgvector、RRF、Reranker、Evidence Gate 和 Trace；
3. 比较召回、排序、任务/方向判断和各阶段延迟；
4. 回放结果不得进入用户回答；
5. 只有技术设计定义的全部发布阈值通过，Phase 6 切换才算完成。

旧链 feature flag 与短期实现回滚开关不再补建。运行时只保留 Corpus 原子回滚；检索实现
回滚只允许使用仍基于统一 Corpus，且通过 legacy detector、schema/readiness 和 Golden
safety smoke 的已审核 Git 版本。旧检索实现永不作为回滚目标。

## 后果

- 优点：不伪造历史证据，不为形式验收恢复高风险旧链，最终状态保持单一检索通道。
- 代价：无法证明迁移窗口内“只有旧链生成答案”的历史过程；该缺口由本 ADR 明确接受。
- 放行条件：架构所有者批准本提案；Golden 120 Gate、Source Coverage、Trace 完整率和
  legacy detector 全部通过；回放报告记录新链召回、排序、任务/方向判断和各阶段延迟。
  旧链只作为定性历史参考，不声称存在不可验证的 old/new 延迟对比。
