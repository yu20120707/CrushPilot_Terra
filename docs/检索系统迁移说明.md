# 检索系统迁移说明

## 阶段证据

1. Phase 0：冻结旧链行为和测试基线，建立 120 条脱敏 Golden Dataset。
2. Phase 1：结构化 Skill、全量 Source Manifest 和覆盖 Gate。
3. Phase 2：40 篇 required 文档生成 380 个版本化 Chunk，建立 PostgreSQL/pgvector schema、原子发布和回滚。
4. Phase 3：接入 FTS、Exact Vector、RRF、Reranker、Evidence Gate、Trace 与 Metrics。
5. Phase 4：五节点 LangGraph 接入新 Retrieval Service。
6. Phase 5：以 Golden Dataset 和旧基线做影子对照；未通过阈值时不切换。
7. Phase 6：删除 JSON/关键词计数/完整 Markdown 路由，legacy Gate 必须为 0。

详细任务、CR 和证据位于
[`trellis/retrieval-system-refactor`](../trellis/retrieval-system-refactor)。

## 发布

生产发布使用：

```powershell
py scripts/publish_corpus.py `
  --database-url $env:DATABASE_URL `
  --version 2026.07.5
```

脚本执行 schema、全量扫描、Chunk、中文分词、Embedding、staging 写入、Gate
和原子发布。同版本已经 ready 时脚本幂等退出；失败的 staging 会在重试前清理。
Docker Compose 使用一次性 `corpus-publisher`，成功后才启动后端。

## 切换 Gate

发布前必须依次成功：

```powershell
py scripts/verify_source_coverage.py
py scripts/verify_corpus_version.py
py scripts/verify_traceability.py
py scripts/detect_legacy_retrieval_paths.py
```

真实 PostgreSQL + pgvector 集成测试通过 `TEST_DATABASE_URL` 启用；未配置时
测试会明确 skip，不能作为发布通过证据。
